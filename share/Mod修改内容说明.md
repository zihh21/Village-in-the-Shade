## 当前包含的 Mod

### 1. FishingAutoCatch 钓鱼自动收杆 `v0.3.1`

| 项目 | 内容 |
|---|---|
| 目录 | `src/FishingAutoCatch/`（C# 加载器，net8.0/x64） |
| 生效范围 | 全局（任意地点钓鱼均生效） |
| 热键 | **F8**：开启/关闭；注入后默认开启。由**监控窗口**轮询全局按键（任意界面、任意场景均可切换，不再局限于钓鱼小游戏内）；切换时加载器侧发出提示音（开启 880Hz、关闭 440Hz，各 100ms） |
| 用法 | 运行 `Mods/FishingAutoCatch/FishingAutoCatch.exe`（推荐不带参数进入**监控模式**：自动等待游戏启动后注入、游戏重启后自动重新注入、实时显示 F8 状态与触发次数，按任意键退出监控）；另支持 `--once`（一次性注入）、`--status`（查状态）、`--verify`（健康检查+触发计数）、`--remove`（还原）、`--dump-stub`（调试） |
| 补充 | 每次运行写入 `FishingAutoCatch.log`（exe 同目录），窗口常驻不会一闪而过；F8 开关依赖监控窗口运行（游戏重启后重开本程序即可） |

**功能**：

- 跳过「鱼上钩后拉线节奏小游戏」（CTask_Menu_Fishing 的节奏判定）：
  开启状态下，咬钩进入节奏小游戏后，把全部音符置为"命中"并把判定索引置为音符总数，
  同一帧即自然走到游戏的**正规成功路径**（全部音符命中检查 → 发成功事件 + 消息 0xFB）。
- 与手动打完所有音符完全同一条结算路径：**不修改鱼品质、数量与奖励规则**。
- 保留原流程：**甩竿 → 等咬钩 → 收杆** 的节奏完全不变，仅跳过咬钩后的按键节奏环节。
- 关闭状态下（F8）游戏行为与原版一致（节奏小游戏需手动游玩；不影响漏击失败判定）。

**技术要点**：

- 反编译依据：`village.exe` rva 0x38A860（CTask_Menu_Fishing::update 判定函数）、成功路径 0x38B2E6→0x38B343、
  汇合点 0x38B114、成功检查点 0x38B2F6（call 0x7491b0 时间轴播完判定）。详见 `docs/钓鱼节奏小游戏分析.md`。
- 实现方式：纯 C# 加载器 + **两个 hook 点**：
  - **Hook A**（rva 0x38A860 入口，15 字节 inline detour→164 字节 stub）：开关检查 + 对象守卫（
    任务未完成、音符数组有效且非空、对象状态 [[this+0x240]+0x20]+0x568==0x3F2）+
    全部音符置 2 + 索引置总数 + `gHits` 计数，trampoline 复放 prologue 跳回 `target+15`。
  - **Hook B**（rva 0x38B2FD，6 字节，**随 gEnabled 动态同步**）：开启时把成功检查
    `0F 84 81 01 00 00`（je 0x38B484，跳过成功动作）改为 NOP——绕过 0x7491b0"时间轴播完判定"的阻塞
    （该函数受时间线内部事件状态影响，伪造音符状态不会推进，导致 v0.2.0 卡在小游戏）；
    **关闭时还原原始 je**，恢复原版"等待时间线播完再判定"——否则每个音符被处理（命中/漏击）后
    index 递增即进入 0x38B2E6，NOP 会立刻跑全音符检查导致玩第一个音符就判失败（v0.3.0 的缺陷）。
- stub 不再内置 GetAsyncKeyState/Beep（v0.2.0 为此曾在 call Beep 后写被破坏的 rax，造成"关闭即退出游戏"）；
  热键检测与提示音全部移到加载器进程，F8 变全局且彻底根治崩溃。
- 注入到已注入的进程时会先还原两个旧补丁再重打，避免状态文件与内存不一致。
- Mod 结构：`Program.cs`（入口/CLI）、`Monitor.cs`（监控模式：等待/自动注入/重启重注/实时状态/全局 F8 轮询）、
  `Injector.cs`（分配内存/打双补丁/还原/校验/F8 切换）、`HookStub.cs`（机器码生成器，含对象偏移与反编译注释）、
  `ProcessManager.cs`（定位进程）、`PatchState.cs`（注入状态持久化，含双补丁原始字节）、`Win32Api.cs`（P/Invoke）、`Log.cs`（日志）。

## 更新记录

### 2026-09-23（v0.3.1：修复关闭后小游戏直接失败）

- **修复**：F8 关闭后，钓鱼**不进入节奏小游戏而是直接失败**——Hook B（0x38B2FD NOP）是静态补丁、
  不受 gEnabled 控制。而 0x38B2E6 成功检查在**每个音符被处理后**（index 递增）都会到达：原版中
  `0x7491b0` 返回 0（时间线未播完）时 `je` 退出"继续等待"；NOP 后玩家打完第一个音符（命中或漏击）
  就会立刻执行全音符==2 检查，发现其余音符还是 0/1/3 → `jne 0x38B4B1` 立即判失败，小游戏形同没有。
- **调整**：Hook B 改为**动态同步**——F8 开启→写入 NOP（自动判定生效）；F8 关闭→还原原始
  `0F 84 81 01 00 00`（恢复原版"等待时间线播完再判定"，关闭=完全原版行为）。监控窗口每次 F8 切换
  后立即同步，且每轮轮询自愈校验（检测到不一致自动修正并打印 `[自愈]`）；`--verify` 同步校验
  Hook B 与开关状态的一致性。
- **说明**：v0.3.0 的开启路径（Hook A 每帧全音符=2 + index=总数 + Hook B NOP）不受影响；
  stub 字节未变（SHA256 仍为 `ADF28D67...05E90B7`）。

### 2026-09-23（v0.3.0：修复卡小游戏、F8 全局化、根治关闭崩溃）

- **修复**：开启功能后钓鱼**卡在本应跳过的小游戏**——根因是成功路径 0x38B2F6 调用 `0x7491b0`
  （"时间轴/谱面播完判定"，受时间线内部事件树状态影响；伪造音符状态不会推进它）返回 0 时
  `0x38B2FD je 0x38B484` 直接退出本帧、永不置完成标志。新增 **Hook B**：把 0x38B2FD 的
  `0F 84 81 01 00 00` 改为 6 字节 NOP，音符达标后无条件走正规成功动作（成功事件+消息 0xFB）。
- **修复**：F8 **只有在钓鱼小游戏内按才有效**——v0.2.0 的 F8 检测在 stub 内（仅钓鱼 update 执行）。
  现改为由监控窗口用 `GetAsyncKeyState` 轮询全局键盘状态（该 API 与焦点无关），**任意界面/场景**下按 F8 都可切换；
  监控窗口收到 F8 后通过进程句柄翻转游戏内 `gEnabled`。
- **修复**：按 F8 **关闭即退出游戏**——v0.2.0 stub 内 `call Beep` 后 rax 被破坏，随后 `mov byte[rax],1`
  向随机地址写入导致访问冲突。现已将热键检测与提示音整体移出 stub（stub 不再调用任何外部 API），
  崩溃源彻底移除。
- **调整**：stub 从 280 字节精简为 164 字节（去掉 GetAsyncKeyState/Beep/lastF8 段），
  新增 Hook B 补丁管理与状态文件 `original2` 记录；capstone 逐指令校验通过、两次 dump SHA256 一致。
- **说明**：Hook B 在关闭状态下仅把"手动打完音符后等待时间线播完"提前为"打完即成功"，与原版几乎无感；漏击失败判定不受影响。

### 2026-09-23（v0.2.0：修复闪退与 F8 提示）

- **修复**：双击 exe"打开窗口直接闪退"——原版是控制台跑完即关、无输出可读；现改为
  **默认进入监控模式**（窗口常驻），异常全量写入 `FishingAutoCatch.log`，运行结束后保留窗口提示。
- **修复**：钓鱼系统"没有任何变动"——主要诱因是游戏未启动/重启后未重新注入；
  监控模式会自动等待游戏进程、注入，并在游戏重启后**自动重新注入**，无需再手动踩时机。
- **新增**：F8 开启/关闭提示——游戏内发出提示音（开启 880Hz / 关闭 440Hz，100ms），
  监控窗口同步滚动显示开关状态与"自动判定已触发 N 次"。
- **新增**：stub 内 `gHits` 命中计数器 + `--verify` 健康检查（Hook 是否在位、触发次数），便于确认 Mod 实际生效。
- **新增**：防重复注入保护（先还原旧补丁再重打）；默认保持开启行为不变。
