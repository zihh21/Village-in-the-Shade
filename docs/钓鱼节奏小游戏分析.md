# 钓鱼节奏小游戏分析

> 本文档为 `docs/反编译代码索引文档.md` 中"钓鱼节奏小游戏"模块的详细分析。
> 依据 `village.exe`（ImageBase 0x140000000）反汇编 `out_38A860.txt`、`out_38ABE0.txt`、
> `out_38AF0A.txt`、`out_38B2C0.txt`、`out_388B30.txt` 及补充切片编写。

## 1. 触发链与对象关系

1. 玩家装备鱼竿 → `CState_Player_FishingRod`（注册 foff 0x1068F00，`checkFishingEnable` rva 0x100DFD0、`update_Inner` rva 0x100E040）负责"甩竿→等咬钩→收杆"。
2. 咬钩后创建/激活任务 `CTask_Menu_Fishing`（构造函数 rva 0x388B30）。
   - +0x218/21c/220 位置默认值；+0x224=6.0、+0x22C=5.0（前后判定窗口）；+0x228=60.0（激活提前量）。
   - 尾部 `lea r9,[0x388DD0]; r8d=5; call 0x7671a0` 注册 **update 回调**（rva 0x388DD0 = `jmp 0x38A860` 的独立 stub）。
3. 音符由 builder rva 0x388F50 创建（字符串 `fishing_base`/`notesBase`/`note%02d`/`pos01` 等），填充 `+0x250` 数组：每元素 8 字节 `{float 时间; int 状态}`，数组结束指针在 `+0x258`。
4. 节奏小游戏"运行中"的判据：`[[this+0x240]+0x20]+0x568 == 0x3F2`（rva 0x38A9D7 检查），且 `[this+0x248] == 0`（未完成）。

## 2. 音符状态机

| 状态 | 含义 | 设置点 |
|---|---|---|
| 0 | 未激活（时间未到） | 初始化 |
| 1 | 可击（进入激活窗口） | rva 0x38AF56：`currentTime > 音符时间−+0x228` 且状态为 0 |
| 2 | 命中（判定成功） | rva 0x38AA5E：输入按下 + 时间在 `[时间−+0x224, 时间++0x224]` 内 + 状态为 1 |
| 3 | 漏击（判定失败） | rva 0x38AC10 / 0x38B14C；**漏击后不再可能成功**，这是"鱼跑掉"的直接来源 |

- 判定索引 `+0x268`：命中/漏击后经 0x38B2D8→0x38B2E0 自增。
- 隐藏失败检查 0x38B12B：`currentTime > 音符时间++0x224` 且状态≠1 ⇒ 置 3（漏击）。

## 3. 成功路径（重点）

汇合点 **rva 0x38B114**（每次 update 都会到达）：

```
0x38B114: movsxd rax, dword [this+0x268]   ; 当前索引
0x38B11B: r8  = [this+0x258] − [this+0x250]; sar r8,3   ; 音符总数
0x38B122: cmp eax, r8d
0x38B125: jge 0x38B2E6                    ; ★索引 >= 总数 → 直接进入成功检查
0x38B12B: （否则隐式漏击检查...）
0x38B2D8: mov rcx,this; call 0x38B640      ; 每次音符结果后的辅助
0x38B2E0: inc dword [this+0x268]           ; 索引+1
0x38B2E6: rcx=[[this+0x238]+0x20]; call 0x7491b0(0, 0)  ; "时间轴播完"判定
0x38B2FB: test al,al
0x38B2FD: je 0x38B484                     ; ★★ al==0 → 退出本帧（不置完成标志）→ 卡小游戏的根因
0x38B303: cmp byte [this+0x248],0 ; jne 退出
0x38B310: mov byte [this+0x248],1          ; 置完成标志
0x38B317..341: 遍历全部音符，要求 state==2，任一不满足 → 0x38B640 回退退出
0x38B343: ★成功：向对象发送事件（字符串 rva 0xE354E0）+ 消息 0xFB + SE（0x10E7B78 单例）
```

### 3.1 成功检查 `0x7491b0` 的阻塞（v0.3.0 前"卡小游戏"根因）

`0x38B2F6 call 0x7491b0` 是**时间轴/谱面"已全部播完"判定**（0x7491b0–0x749331，通用时间轴系统，非钓鱼特有）。其返回 1 需要同时满足：

| 条件 | 含义 |
|---|---|
| `[rcx+8] != 0` 且 `[[rcx+8]+0xdc] != 0` | 时间轴宿主对象有效 |
| `[rcx+0x558] != 0` | 子对象（乐谱容器）有效 |
| `[rcx+0x568] != 0` | 播放器状态非 0 |
| `[rcx+0x8d0]`（r11 时间轴）`[r11+0xb0] == 0` | 无激活中的播放片段 |
| `0x740970(r11,0)` 当前时间 `>= [r11+0xb8]` | 时间戳已越过总长（0x740970 读全局用户态计时，单调推进） |
| `[r11+0x90..0x98]` 队列内每个节点 `0x740c60` 返回 1 | 子节点递归满足上述条件（`[+0xb0]==0`、时间≥`[+0xb8]`、子树为空） |

任一不满足即返回 0 → `0x38B2FD je 0x38B484` 直接退出本帧，**永不置完成标志**。

> **关键结论（v0.3.0 修复依据）**：该判定受时间轴内部事件树状态（`0x8d0` 下的 `b0/b8/90/98` 节点）影响，
> 而**这些内部状态只能由"音符命中/推进"代码路径更新**——入口 stub 只把音符数组全部置 2 并不会推进时间轴，
> 因此 v0.2.0 时 0x7491b0 恒返回 0，游戏卡在本应跳过的小游戏上。
> v0.3.0 起将 `0x38B2FD` 的 `je`（`0F 84 81 01 00 00`）替换为 6 字节 NOP，**音符达标后无条件执行成功动作**，
> 彻底绕开该阻塞（0x7491b0 本身是纯查询、无副作用，跳过安全；成功动作不依赖时间轴对象）。

结论：开启状态下，入口 stub 把全部音符置 2 且把 `[this+0x268]` 置为总数后，配合 Hook B（0x38B2FD NOP），
同一帧即走 0x38B125 分支进入成功动作——全音符==2 检查必然通过，与"手动打完所有音符"基本同路径，
结算完全正规（不改品质/数量）。

## 5. Hook 设计（v0.3.0，双 Hook 点）

- **注入方式**：纯 C# 加载器（`src/FishingAutoCatch/`）向运行中的 `village.exe` 分配内存（VirtualAllocEx），
  写入 164 字节 stub（`HookStub.cs` 生成，代码 164 字节 + gEnabled@164 + gHits@165），再打两个补丁：
  - **Hook A**（rva 0x38A860，15 字节）：`jmp [rip+0] → stub`，覆盖
    `mov rax,rsp / mov[rax+10],rbx / mov[rax+18],rsi / mov[rax+20],rdi`；
  - **Hook B**（rva 0x38B2FD，6 字节）：`0F 84 81 01 00 00`（je 0x38B484）→ 6×NOP，
    绕过 0x7491b0 的成功阻塞（见 §3.1）。
- **stub 逻辑**（按进入顺序）：
  1. 读 `gEnabled`（由监控窗口 F8 翻转）——关闭 → 复放原 prologue 跳回，完全不影响游戏；
  2. 守卫：[+0x248]==0（未完成）、音符数组非空（[+0x250]/总数>0）、
     `[[+0x240]+0x20]+0x568==0x3F2`（已咬钩进入节奏小游戏）；
  3. 执行：全部音符 state=2，`[+0x268]`=总数，`gHits`+1（诊断计数）；
  4. 复放 15 字节原 prologue，`jmp [rip+0] → target+15` 回原函数。
- **stub 只使用易失寄存器**（rax/rdx/r8/r9/r11），不改 rbx/rsi/rdi/xmm，不调用任何外部 API，保证语义一致。
- **热键（F8）**：不再由 stub 检测（v0.2.0 的做法局限在钓鱼 update 内且存在 call Beep 破坏
  rax 导致"关闭即退出游戏"的缺陷）。v0.3.0 由**监控窗口**每 100ms 调 `GetAsyncKeyState(VK_F8)`
  （该 API 反映全局键盘状态，与窗口焦点无关），检测到按下沿即通过进程句柄翻转游戏内 `gEnabled`
  并在加载器侧 `Beep` 发声——任意界面/场景都能切换。
- 效果：咬钩后第一帧即自然完成小游戏；甩竿→等咬钩→收杆流程完全保留；F8 全局随时开关；全局生效。

## 6. 验证记录

- `dotnet build -c Release` 编译通过（net8.0，x64，0 警告 0 错误）。
- stub 机器码经 `--dump-stub` 输出后用 capstone 逐指令核对：38 条指令全部正确，覆盖 164 字节
  （含 trampoline 复放、SIB `r8+r9*8+4`、`movabs` 2 个 imm64 槽、resume 槽 target+15）；两次 dump SHA256 一致
  （`ADF28D67FE3A3104531E92A254625F342303370D358896733FEF5F2AD05E90B7`）。
- Hook B 原始字节核对：0x38B2FD 处确为 `0F 84 81 01 00 00`（je rel32 → 0x38B484）。
- 对运行中的游戏进程完成注入，`ProtectWriteVerify` 回读校验通过；`--status`/`--verify` 确认开关默认开启。
- 实测建议：游戏内钓鱼咬钩后确认小游戏自动完成并获得鱼获；保持监控窗口运行，任意场景按 F8 切换并听提示音（开启 880Hz/关闭 440Hz）。
