# 钓鱼节奏小游戏分析

> 本文档为 `docs/反编译代码索引文档.md` 中"钓鱼节奏小游戏"模块的详细分析。
> 依据 `village.exe`（ImageBase 0x140000000）反汇编 `out_38A860.txt`、`out_38ABE0.txt`、
> `out_38AF0A.txt`、`out_38B2C0.txt`、`out_388B30.txt` 及补充切片编写。

## 1. 触发链与对象关系

1. 玩家装备鱼竿 → `CState_Player_FishingRod`（注册 foff 0x1068F00，`checkFishingEnable` rva 0x100DFD0、`update_Inner` rva 0x100E040）负责"甩竿→等咬钩→收杆"。
2. 咬钩后创建/激活任务 `CTask_Menu_Fishing`（构造函数 rva 0x388B30）。
   - +0x218/21c/220 位置默认值；+0x224=6.0、+0x22C=5.0（前后判定窗口）；+0x228=60.0（激活提前量）。
   - 尾部 `lea r9,[0x388DD0]; r8d=5; call 0x7671a0` 注册 **update 回调**（rva 0x388DD0 = `jmp 0x38A860` 的独立 stub）。
3. 音符由 builder rva 0x388F50 创建（字符串 `fishing_base`/`notesBase`/`note%02d`/`pos01` 等），填充 `+0x250` 数组：每元素 8 字节 `{float 时间; int 状态}`，数组结束指针在 `+0x258`。
4. 节奏小游戏"运行中"的判据：`[[this+0x240]+0x20]+0x568 == 0x3F2`（rva 0x38A9D7 检查），且 `[this+0x248] == 0`（未完成）。

## 2. 音符状态机

| 状态 | 含义 | 设置点 |
|---|---|---|
| 0 | 未激活（时间未到） | 初始化 |
| 1 | 可击（进入激活窗口） | rva 0x38AF56：`currentTime > 音符时间−+0x228` 且状态为 0 |
| 2 | 命中（判定成功） | rva 0x38AA5E：输入按下 + 时间在 `[时间−+0x224, 时间++0x224]` 内 + 状态为 1 |
| 3 | 漏击（判定失败） | rva 0x38AC10 / 0x38B14C；**漏击后不再可能成功**，这是"鱼跑掉"的直接来源 |

- 判定索引 `+0x268`：命中/漏击后经 0x38B2D8→0x38B2E0 自增。
- 隐藏失败检查 0x38B12B：`currentTime > 音符时间++0x224` 且状态≠1 ⇒ 置 3（漏击）。

## 3. 成功路径（重点）

汇合点 **rva 0x38B114**（每次 update 都会到达）：

```
0x38B114: movsxd rax, dword [this+0x268]   ; 当前索引
0x38B11B: r8  = [this+0x258] − [this+0x250]; sar r8,3   ; 音符总数
0x38B122: cmp eax, r8d
0x38B125: jge 0x38B2E6                    ; ★索引 >= 总数 → 直接进入成功检查
0x38B12B: （否则隐式漏击检查...）
0x38B2D8: mov rcx,this; call 0x38B640      ; 每次音符结果后的辅助
0x38B2E0: inc dword [this+0x268]           ; 索引+1
0x38B2E6: rcx=[[this+0x238]+0x20]; call 0x7491b0(0, 0)  ; 小游戏推进判定
0x38B303: cmp byte [this+0x248],0 ; jne 退出
0x38B310: mov byte [this+0x248],1          ; 置完成标志
0x38B317..341: 遍历全部音符，要求 state==2，任一不满足 → 0x38B640 回退退出
0x38B343: ★成功：向对象发送事件（字符串 rva 0xE354E0）+ 消息 0xFB + SE（0x10E7B78 单例）
```

结论：**只要把所有音符 state 置 2 且把 `[this+0x268]` 置为总数，同一帧即走 0x38B125 分支进入成功路径**，
且全音符==2 检查必然通过——与"手动打完所有音符"走的是同一条代码路径，结算完全正规（不改品质/数量）。

## 5. Hook 设计（rva 0x38A860 入口 detour）

- **注入方式**：纯 C# 加载器（`src/FishingAutoCatch/`）向运行中的 `village.exe` 分配内存（VirtualAllocEx），
  写入 230 字节 stub（`HookStub.cs` 生成，228 字节代码 + 2 字节开关状态），再在入口写入 15 字节
  `jmp [rip+0] → stub`（覆盖 `mov rax,rsp / mov[rax+10],rbx / mov[rax+18],rsi / mov[rax+20],rdi`）。
- **stub 逻辑**（按进入顺序）：
  1. F8 沿触发切换全局开关（GetAsyncKeyState，edge detect：gLastF8）；
  2. 开关关闭 → 复放原 prologue 跳回，完全不影响游戏；
  3. 守卫：[+0x248]==0（未完成）、音符数组非空、`[[+0x240]+0x20]+0x568==0x3F2`（已咬钩）；
  4. 执行：全部音符 state=2，`[+0x268]`=总数；
  5. 复放 15 字节原 prologue，`jmp [rip+0] → target+15` 回原函数。
- **stub 只使用易失寄存器**（rax/rcx/rdx/r8/r9/r10/r11 与栈 push/pop），不改 rbx/rsi/rdi/xmm，保证与原代码语义一致。
- 效果：咬钩后第一帧即自然完成小游戏；甩竿→等咬钩→收杆流程完全保留；F8 随时开关；全局生效。
